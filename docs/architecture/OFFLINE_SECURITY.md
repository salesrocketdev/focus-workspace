# Local-first, sync and security

Core operates without account/network. Persist sessions, activities, tasks, layouts and preferences locally; show cached calendars with last successful sync and stale state. No background guarantees when suspended. If storage fails, show recoverable error and do not claim saved. Export local data before destructive reset. Schema migrations tested with prior fixtures.

Remote sync P1: explicit opt-in, authenticated profile, per-record versions, idempotent operation IDs and tombstones; queue retries with backoff, document merge rules. Layout conflicts require explicit choice or revision-safe update, not silent overwrite. For active session cross-device ownership, design lease/conflict resolution before release; no two devices double-counting same session. Do not promise seamless offline multi-device ownership. Server encrypt provider tokens at rest with managed key/env configuration; never log raw tokens, meeting details or authorization callbacks. TLS, scoped auth, input validation and user isolation. Local-only profile not forced into cloud. Disconnect and data deletion explained. Telemetry off by default; no tracking browsing or work activity. Before public release review OAuth verification, threat model, dependency audit, license and provider policies.
