# Book metadata and reading plans — #35

Related: #19 reading library, #33 prototype approval. Status: prototype mock; production not implemented.

## UX
Activities → Readings → Search book → search by title, author or ISBN → choose edition → review cover, metadata and editable title/author/pages → optionally import available contents → import into library. Manual entry is always available. Book details show page progress and independent chapter completion. Missing page count must be supplied manually; missing contents can be entered manually. Do not fabricate metadata.

## Prototype
Local fictional catalogue, three editions, illustrative covers generated by the existing Cover component. Search, empty results, duplicate edition prevention, missing pages and contents, manual fallback, review and import, chapter completion and adding chapters are interactive. Existing shared book state feeds the dashboard and immersive timer. Data remains in memory, consistent with the current prototype. No external requests, API keys, EPUB parser or real bibliographic claims. The fictional ISBNs and editions are only fixtures.

## Production
Define a provider adapter with normalized edition and work identifiers, optional cover URL, page count, language, publisher, year, ISBN and optional structured contents. Open Library first, use search results to discover editions and fetch specific edition data; store provenance and don't treat work-level aggregate page counts as exact edition counts. Check provider rate limits, attribution, API and image usage terms before release. Debounce/cancel requests, cache bounded results, handle offline, loading, error and missing cover. Never require provider access to edit a saved book. Duplicate by edition identifier or ISBN; allow distinct editions. Google Books fallback only after key/quota/privacy review. Local EPUB metadata/TOC import as separate work; no ebook reader or full text. Persist user corrections and chapter completion independently from page and timer progress. No reading activity sent to providers by default.

## Acceptance
See issue #35. Production gate: #19 and relevant M0 foundations. Test provider contracts with fixtures and real responses; test mobile WebKit, offline storage and accessible cover fallback.
